The Grid over MCP

Ask Claude, ChatGPT or Gemini about fires, evacuations, roads, weather and power on the Ebbetts Pass / Highway 4 corridor. The assistant reads The Grid through the Model Context Protocol (MCP).

public · read-only · no sign-in · Streamable HTTP

# The server

Server URL      https://data.sierragridteam.org/mcp
Authentication  none
Name            Sierra Grid   # any name works

That URL is this page. A browser gets these instructions; an MCP client POSTs to it and gets the protocol.

The steps below follow each vendor's help page as of November 2026. Menus move: where they differ, the linked page is right.

> Claude

  1. Open Customize, then Connectors (claude.ai/customize/connectors).
  2. Click + Add, then Add custom connector.
  3. Give it a name, paste the server URL, and click Continue.
  4. Under Authentication choose No sign in, then click Add.
  5. In a chat, click +, then Connectors, and turn it on.
  • Every plan can add custom connectors; the Free plan is limited to one.
  • Once added it also works in Claude Desktop and the mobile apps.
  • On Team and Enterprise an owner adds it first, under Organization settings, Connectors, Add, Custom, Web. Members then click Connect.
# Claude Code
$ claude mcp add --transport http sierra-grid https://data.sierragridteam.org/mcp

Anthropic's instructions: custom connectors using remote MCP.

> ChatGPT

  1. On the web, open chatgpt.com/plugins.
  2. Select the plus button, then Add custom MCP server.
  3. Give it a name. Under Connection, paste the server URL.
  4. Set authentication to No authentication.
  5. Read the risk warning, select I understand and want to continue, then Create as a plugin.
  6. Install the plugin. In a chat, type @ and pick it.
  • A work or school workspace may not let members add servers; ask its admin.

OpenAI's instructions: add a custom MCP server.

> Gemini

  1. On a computer, open gemini.google.com.
  2. Click Settings, then Connected Apps. If it is not there, click Personal Intelligence first.
  3. Under Custom apps, click Add a custom app and paste the server URL.
  4. Click Next and follow the prompts.
  5. In a chat, type @ and pick it. It then works in the mobile app too.
  • Google offers custom apps to personal accounts in the US, age 18 or over, in English, with History turned on.
  • Google's page describes servers that ask you to sign in. This one does not, and we have not confirmed that Gemini accepts it.

Google's instructions: connect and manage custom apps.

> Any other client

Anything that speaks MCP over Streamable HTTP can connect: give it the server URL and no credentials. The server is stateless (one JSON-RPC message per POST, one JSON response, no session, no event stream) and implements protocol revision 2025-06-18.

$ curl -s https://data.sierragridteam.org/mcp \
    -H 'Content-Type: application/json' \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Things to ask

  • What is happening around Arnold right now?
  • Is Highway 4 open over Ebbetts Pass?
  • Are there evacuation orders or warnings in Calaveras County?
  • How did the last road closure near Murphys unfold?
  • Which of The Grid's sources are down?

# What the assistant gets

  • grid_situation what is happening at a place, address or lat,lng
  • grid_events events by place, layer, severity, status, time and text
  • grid_event one event in full
  • grid_search find a fire, road, place, camera or feed by name
  • grid_conditions current weather and fire-weather state
  • grid_history how events changed over a time range
  • grid_resolve an address or lat,lng to the places containing it
  • grid_places the place directory
  • grid_sources the health of every upstream feed
  • search, fetch the same search, in the shape research modes expect

The data is the same as the HTTP API, with map geometry left out.

# Keep in mind

  • Reference only. For an evacuation or a road, follow the source link in the answer and check the official page.
  • No data is not an all-clear. A source marked UNAVAILABLE means its status is unknown. Every result says so, but an assistant can still summarize it wrongly.
  • Read-only. The server has no account, takes no input beyond the question's parameters, and changes nothing.
